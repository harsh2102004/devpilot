🔑 The Core Architectural Breakthrough: Hybrid RAG

Standard RAG platforms take text, chunk it naively every 500 characters, embed it, and pray the LLM gets the context. DevPilot combines two complementary models of understanding:

  • 1. Deterministic Knowledge (Code Graph): Exact symbol coordinates, file-to-file imports, caller-callee call graphs, and dependency trees built with Babel AST compiler theory.
  • 2. Semantic Knowledge (Vector DB): High-dimensional vector embeddings in Pinecone that understand intent (e.g. "where do we handle login?" finds loginUser even if the word "login" isn't explicitly mentioned).

Tech Stack & "Why This Over That?"

Key technical decisions you can defend with confidence in any system design interview.

Interview Talking Points
Babel AST Parser (@babel/parser) AST Engine

Why over Regex / LangChain? Regex splitters break on nested closures, async wrappers (asyncHandler(async (req, res) => {})), and template strings. Babel parses a true Abstract Syntax Tree with verified line numbers (startLine, endLine).

💬 "We didn't rely on brittle regex; we parsed the code down to AST nodes, letting us map function signatures, calls, and imports deterministically."
BullMQ + Redis Async Queues

Why over Direct HTTP? Repository cloning and AST parsing can take anywhere from 5 seconds to 2 minutes. Running this synchronously blocks the Express event loop and triggers HTTP 504 gateway timeouts. BullMQ offloads scans to isolated worker threads with exponential backoff retries.

💬 "HTTP handlers return 202 Accepted immediately with a Job ID. Background workers communicate real-time progress (0-100%) through MongoDB and BullMQ events."
MongoDB (Mongoose) Primary Datastore

Why over PostgreSQL? Code graphs and AST symbol trees are deeply nested, semi-structured documents (arrays of functions, calls, imports, and logs). Document storage enables storing complete CodeGraph snapshots and job logs in a single native format.

💬 "We store summary metrics on the Project document for instant UI rendering, and full node/edge relational trees in a dedicated CodeGraph collection."
Pinecone Vector Database Vector Search

Why Namespaces? Multi-tenancy isolation. Each project's vector embeddings are stored in an isolated namespace (project-${projectId}). When a project is re-scanned, we can delete and rebuild the entire vector index in O(1) time without affecting other projects.

💬 "We isolate vectors by project namespace, preventing cross-tenant code leakage and ensuring atomic index resets on re-scans."

Phase 1 to Phase 5 Engineering Breakdown

What was built, how it works under the hood, and common pitfalls resolved.

5 Phases Complete
Phase 1: Dual-Token JWT Authentication & Security
Completed

Implemented a secure authentication flow using short-lived Access Tokens (1 day) and long-lived Refresh Tokens (10 days) stored in HTTP-only cookies / DB.

Under the Hood:
  • Passwords hashed with bcryptjs (salt factor 10) inside a Mongoose pre('save') hook with isModified('password') guard.
  • Auth middleware extracts bearer token, verifies signature, and normalizes req.user._id to prevent object/string mismatch bugs.
  • Complete ESM architecture ("type": "module") across the entire backend.
Phase 3: Project Cockpit & GitHub Octokit Integration
Completed

Built project lifecycle management with strict IDOR (Insecure Direct Object Reference) prevention and automated GitHub integration via Octokit.

Under the Hood:
  • Ownership Authorization: Every project controller strictly verifies project.owner.toString() === req.user._id.toString() (403 Forbidden otherwise).
  • GitHub Personal Access Token encrypted in User schema with select: false so it is never accidentally exposed in API responses.
  • Octokit service fetches authenticated user repos, branch heads, and clone URLs.
Phase 4: Distributed BullMQ Queues & Background Workers
Completed

Decoupled long-running repository scans from the HTTP server using Redis and BullMQ workers with comprehensive lifecycle state transitions.

Under the Hood:
  • Producer: POST /api/scan/:projectId checks for active duplicate scans (409 Conflict), writes a Job document in MongoDB, and enqueues BullMQ job (returns HTTP 202).
  • Consumer: Dedicated worker process (scanner.worker.js) transitions project from connected ➔ scanning ➔ indexed.
  • Failure Recovery: Captures stack traces, marks Job failed and Project scan-failed.
Phase 5: AST Parser, File Walker & Code Graph Engine
Completed

The brain of DevPilot: recursively crawls repositories, parses AST syntax trees, resolves canonical import paths, and constructs relational code graphs.

Under the Hood:
  • File Walker (fileWalker.service.js): Recursive crawler with ignore rules (node_modules, .git, lockfiles), 1MB security limit, and JS/TS extension filters.
  • AST Visitor (ast.services.js): Uses Babel to extract function declarations, arrow functions inside higher-order wrappers (like asyncHandler), classes, params, imports, and call expressions.
  • Relative Path Resolver: Maps ../models/job.js to canonical repo paths, handling extension omission (.js, .ts, /index.js) and separating npm packages from internal files.
  • Code Graph (codeGraph.service.js): Produces 4 node types (file, function, class, package) and 3 edge types (defines, imports, calls).
  • Live Verification: Tested on server source; indexed 96 nodes and 192 edges in under 5 seconds!

System Design Why did you use BullMQ and Redis instead of handling scans directly in the Express request?
▼

Repository analysis involves file I/O, git shallow cloning, and CPU-intensive AST parsing. In Node.js, the event loop is single-threaded. If an Express route performed AST parsing synchronously:

  1. The event loop would be blocked, freezing all other incoming API requests for all users.
  2. HTTP client requests would hit standard 30-60 second timeout thresholds (504 Gateway Timeout).
  3. A worker crash would take down the entire web server.

By using BullMQ, we adopt the Asynchronous Request-Reply Pattern: the API returns HTTP 202 Accepted immediately with a Job ID. Background worker processes handle execution, publish progress events, and automatically retry on transient failures.

💡 Interviewer Follow-up: "What happens if Redis goes down while a scan is running?"
Answer: BullMQ uses Redis persistence (RDB/AOF). Jobs in progress become stalled; when the worker restarts or reconnects, BullMQ detects stalled jobs and either moves them to the failed queue or retries them based on the attempts policy.
Event Loop Non-blocking HTTP 202 Accepted Exponential Backoff Worker Decoupling
Compiler & AST Why did you build an AST parser instead of using regular expressions or LangChain's splitters?
▼

Regular expressions cannot parse context-free grammars (Chomsky hierarchy). Code has nested structures: closures, callbacks, higher-order functions (e.g. asyncHandler(async (req, res) => {})), and template strings with embedded brackets.

LangChain's RecursiveCharacterTextSplitter.fromLanguage() relies on regex heuristics like \nfunction . In modern codebases:

  • It fails to identify functions wrapped in decorators or higher-order functions.
  • It cannot extract parameter names (params: ['req', 'res']) or determine if a function is asynchronous.
  • It slices through blocks, producing syntax errors in chunks.

By utilizing Babel's AST parser (@babel/parser + @babel/traverse), we generate a true Abstract Syntax Tree, extracting exact 1-indexed line coordinates (startLine, endLine) that align 1-to-1 with our Code Graph nodes and Pinecone vector IDs.

💡 Interviewer Follow-up: "How do you handle JSX and TypeScript files?"
Answer: In ast.services.js, we configure Babel parser plugins: plugins: ['jsx', 'typescript']. This enables parsing both standard JavaScript and TypeScript/React syntax trees seamlessly.
Abstract Syntax Tree Visitor Pattern Higher-Order Wrappers Deterministic Slicing
Security How does DevPilot protect against IDOR (Insecure Direct Object Reference) and unauthorized repository access?
▼

We implement multi-layered authorization across all controllers:

  1. JWT Verification Middleware: Extracts the bearer token, verifies signature with ACCESS_TOKEN_SECRET, and attaches the authenticated user document to req.user.
  2. Resource Ownership Enforcement: Every project route (GET, PUT, DELETE, POST /scan, GET /graph) looks up the project and strictly validates: 
    if (project.owner.toString() !== req.user._id.toString()) {
    throw new ApiError(403, "You do not have permission to access this project");
}
  3. Credential Redaction: Sensitive credentials like githubAccessToken are configured with select: false in Mongoose so they are never leaked in API payloads or serialized to client responses.
💡 Interviewer Follow-up: "How do you clone private repositories without exposing the token in process logs?"
Answer: In repoCloner.service.js, if a git clone error occurs, we sanitize the error message with a regex replacer (replace(/https:\/\/[^@]+@github\.com/g, "https://***@github.com")) before logging or throwing.
IDOR Prevention Mongoose select: false Credential Sanitization 403 Forbidden
RAG & Vector DB What is AST-Aware Chunking and why is it superior for code embeddings?
▼

In standard document RAG, sentences and paragraphs have natural semantic boundaries. In code, the semantic unit of computation is the function or the class.

If an embedding chunk cuts off halfway through a function body:

  • The vector representation loses the return statement, the closing logic, and the parameter context.
  • The cosine similarity score against natural language questions drops drastically.

DevPilot's AST-Aware Chunking:

  1. Slices along verified AST function/class line boundaries (startLine to endLine).
  2. Prepends a standardized Context Banner (File, Symbol Name, Parameters, Async status) that gives the vector model rich semantic breadcrumbs.
  3. Assigns deterministic chunk IDs that match the MongoDB Code Graph nodes for Hybrid Retrieval.
Semantic Units Context Breadcrumbs Cosine Similarity Hybrid RAG
System Design How would you scale DevPilot to handle 10,000 repositories concurrently?
▼

Scaling DevPilot from a prototype to a high-throughput enterprise platform requires addressing three primary bottlenecks:

  1. Horizontal Worker Scaling (Kubernetes / KEDA): Decouple the worker into a separate container image. Use KEDA (Kubernetes Event-driven Autoscaling) to scale worker pods up or down based on the BullMQ queue depth.
  2. Distributed Redis Cluster: Replace single-node Redis with Redis Cluster or AWS ElastiCache with read replicas to handle thousands of queue events per second.
  3. Ephemeral Sandboxed Execution: Never run git clone or test execution directly on the host VM. Spin up ephemeral Docker containers or gVisor microVMs (Phase 8) to isolate malicious code and protect system disk space.
  4. Vector DB Indexing Batching: Queue Pinecone vector upserts in batches of 100 vectors with rate-limit backoffs to avoid hitting Pinecone API rate limits during massive scans.
KEDA Autoscaling Redis Cluster gVisor MicroVMs Batch Upserting

Architectural Limitations & Trade-offs

Honest engineering trade-offs that show senior architectural maturity in interviews.

Senior Talking Points
⚠️ Dynamic Runtime Imports

Static AST analysis cannot resolve dynamic runtime module paths like import(`./plugins/${pluginName}`) because the variable value only exists during runtime execution.

💡 Solution / Defense: "We flag dynamic import expressions as external or unresolved nodes, and supplement them during test execution analysis."
⚠️ Large Monorepo Memory Limits

Parsing a 500,000-line monorepo in a single Node process can consume substantial RAM and hit Node's default heap limit (1.4GB).

💡 Solution / Defense: "We enforce a 1MB file cap in FileWalker and process files in sequential worker streams rather than loading all ASTs into RAM simultaneously."
⚠️ Multi-Language Parser Support

Babel is specialized for JavaScript and TypeScript. Scanning Python, Go, or Rust codebases requires language-specific parsers.

💡 Solution / Defense: "In future iterations, we can abstract the parser interface to Tree-sitter, which provides unified C-bindings for 40+ programming languages."
